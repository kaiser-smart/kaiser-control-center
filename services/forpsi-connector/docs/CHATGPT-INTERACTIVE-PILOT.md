# Interaktivní osobní čtecí pilot Forpsi ↔ ChatGPT

Stav PR #209, 26. 9. 2026. Analýzu obsahu provádí model v aktivním chatu přes MCP. Serverový OpenAI API adaptér zůstává volitelný a v osobním pilotu se nespouští. Lokální testy s připravenými závěry neprokazují porozumění modelem ChatGPT ani skutečné vykreslení karty v ChatGPT.

## Tok a hranice

1. Cloudflare `@cloudflare/workers-oauth-provider` poskytuje OAuth autorizační kód, PKCE S256, klientská metadata CIMD a neprůhledné přístupové a obnovovací tokeny v `OAUTH_KV`. Stránka `/authorize` ověřuje stávající relaci SO.ai, přes Service Binding předá pouze serverově zjištěné stabilní ID a samostatně zobrazí souhlas s `forpsi:read`. SO.ai cookie se do MCP ani ChatGPT nepředává. `Store.identity` vyžaduje serverově ověřenou vazbu na existující SO.ai principal a grant ke schránce; shoda e-mailové adresy nestačí. `PERSONAL_PILOT_PRINCIPAL_ID` a `PERSONAL_PILOT_MAILBOX_ID` omezí celý veřejný MCP endpoint na jednu osobu a schránku. Přístup se znovu kontroluje při každém volání. Povolení lze odebrat v `/forpsi-access/`.
2. `begin_mail_setup` vyžaduje souhlas a dovolí nejvýše 30 dní, pouze INBOX a konfigurované Odeslané. `analyze_mail_history` uloží maximálně 50 metadatových záznamů celkem; aktuální okno čte nejvýše 20 z každé složky. `read_setup_sample` vrací po nejvýše pěti zprávách přímo do modelově viditelného výsledku autorský text, role účastníků, referenci a stav pokrytí. Nativní IMAP přístup je read-only. Neprozkoumaná pošta zůstává výslovně neprozkoumaná.
3. Model v chatu posoudí obsah a podá `submit_setup_analysis`: jednotlivé závěry s přesnou citací, priority konkrétních příchozích zpráv, návrhy kontaktů a případný podpis z vlastních Odeslaných. Server před uložením znovu čte citované zprávy, ověřuje přesný text, reference v doručeném vzorku, odesílací identitu podpisu a verzi návrhu. Výsledkem je neschválený návrh. Chybný význam citace může stále odhalit až uživatel při kontrole; samotná citace není důkazem správné interpretace.
4. `answer_mail_setup` ukládá individuální odpovědi. Aktivace profilu a podpisu je povolena jen přes přihlášenou stránku SO.ai pro přesnou verzi návrhu; parametr modelu `confirmed=true` nestačí. `start_worklist(view=priority)` používá uložené priority od ChatGPT a případné výslovné uživatelské opravy. Ostatní zprávy nechává k ručnímu posouzení. Pevné číslování, navigace `review_worklist` omezená na Další/Předchozí a `resume_worklist` dovolí obnovu pozice v novém chatu; `render_worklist` zobrazuje stejný uložený seznam.
5. Veřejné nástroje pilotu neobsahují odesílání, koncepty, příznaky, přesun, mazání ani plánované běhy. Přepínač `CONNECTOR_ENABLED=false` okamžitě vypne veřejné MCP bez zásahu do interní SO.ai pošty. `WORKFLOW_SYNC_ENABLED=false` a `SEND_ENABLED=false` se při případném zapnutí pilotu nastaví zvlášť.

## Stav osobního nasazení a otevřená chyba

Po výslovném schválení osobního pilotu bylo obnoveno Cloudflare oprávnění `workers_kv:write`, vytvořen samostatný `OAUTH_KV`, bezpečně připnut jeden serverově ověřený principal a jedna pilotní schránka, zapnut pouze čtecí veřejný MCP Worker a nasazena jeho SO.ai autorizační stránka. Produkční autorizační stránka přes skutečný ChatGPT CIMD zobrazila přihlášenému pilotnímu uživateli souhlas `forpsi:read`. V ChatGPT vznikla soukromá aplikace „Forpsi – osobní čtecí pilot“ s MCP URL `https://smart-odpady.ai/mcp`.

První připojení aplikace skončilo Cloudflare chybou 1101 během OAuth průchodu. ChatGPT stále nabízí „Připojit“; připojený token, načtení skutečné pošty, modelovou analýzu a vykreslení karty proto nelze potvrdit. Chybová diagnostika probíhá. Žádný další firemní OAuth poskytovatel ani OpenAI API klíč nejsou pro interaktivní pilot potřeba. Plánovač a odesílání zůstávají vypnuté.

## Ověření a návrat

Lokální testy používají syntetickou poštu. Testují dávkování, citace, čas relativního termínu podle data zprávy, odmítnutí cizího principala, neexistenci mutačních nástrojů, stálé pořadí dle modelově vložených priorit a pokračování seznamu. Samostatné testy Pages ověřují nepřihlášeného a cizího uživatele, původ POST, vazbu SO.ai relace a nepředání SO.ai cookie do MCP. Místní skutečný Workerd se syntetickými CIMD metadaty úspěšně prošel: souhlas → kód → výměna s PKCE S256 → `tools/list` → odebrání grantu → zamítnutí původního tokenu. Databázové migrace 0005–0008 byly nejdříve vyzkoušeny na odděleném exportu skutečné D1 se stavem `PRAGMA integrity_check=ok` a poté aplikovány aditivně na produkční D1. Před změnou vznikl soukromý SQL export a Git bundle v adresáři `backups/` mimo Git. Vypnutí pilotu: nastavit `CONNECTOR_ENABLED=false` a nasadit jen samostatný Forpsi Worker; jeho interní SO.ai poštovní cesta zůstává oddělená. Návrat databáze je připraven ze zálohy, avšak není nutný k okamžitému vypnutí čtecího endpointu.
